# Техническое задание на разработку веб-приложения  «Система тестирования»
## Введение: 
Веб-приложение предназначено для организации и проведения онлайн-тестирования студентов образовательных учреждений. Система позволяет преподавателям создавать тесты, управлять процессом тестирования и анализировать результаты, а студентам – проходить тестирование дистанционно, независимо от местонахождения. Использование веб-приложения снижает временные и организационные затраты, связанные с проведением очного тестирования, и повышает удобство взаимодействия между участниками образовательного процесса.

## Цель разработки системы: 
создание веб-приложения для автоматизации процесса тестирования, включающего создание тестов, проведение тестирования и обработку результатов.

## Задачи системы: 
* реализация регистрации и авторизации пользователей;
* обеспечение возможности создания и редактирования тестов;
* обеспечение прохождения тестов пользователями;
* автоматическая проверка результатов тестирования;
* хранение истории прохождений;
* предоставление статистики и аналитики по результатам тестирования.

## Целевая аудитория:
* Преподаватели средних / высших учебных заведений.
* Студенты средних / высших учебных заведений.

## Роли и права пользователей:
•    Студент:
    o    Проходить тесты.
    o    Смотреть свои результаты.
•    Преподаватель:
    o    Создавать / редактировать тесты.
    o    Предоставлять доступ к тестам.
    o    Формировать ведомость по студенту.
    o    Просматривать общие результаты по тесту.

## Основные пользовательские сценарии:
    1.    Преподаватель: Регистрация  Авторизация  Создание теста  Добавление вопросов  Публикация  Просмотр результатов.
    2.    Студент: Регистрация  Авторизация  Прохождение теста  Получение результата.
    3.    Студент: Авторизация  Просмотр ранее полученных результатов.

## Основные функциональные требования:
•    Конструктор тестов:
    o    Создание вопросов различных типов: одиночный выбор, множественный выбор, открытый вопрос (текст/число).
    o    Работа с мультимедиа: добавление изображений.
    o    Управление банком вопросов: создание категорий, рандомизация.
•    Настройка тестирования:
    o    Ограничение по времени (на весь тест или на каждый вопрос).
    o    Ограничение попыток на тест (одна).
    o    Перемешивание вопросов и ответов для предотвращения списывания.
•    Базовые функции системы:
    o    Регистрация с выбором (пользователь или преподаватель).
    o    Авторизация на сайт через почту и пароль.
•    Процесс прохождения тестирования:
    o    Понятный интерфейс, отображение прогресса и оставшегося времени.
    o    Возможность пропускать вопросы и возвращаться к ним.
    o    Автосохранение ответов (на случай сбоя интернета).
•    Проверка и отчетность:
    o    Автоматическая проверка вопросов.
    o    Мгновенное предоставление результата тестирования.
    o    Аналитика: статистика по пользователям.
    o    Формирование ведомости по пользователю.
•    Базовые меры защиты от списывания:
    o    Запрет на копирование вопросов.
    o    Перемешивание вопросов.
    o    Ограничение времени.

## Ограничения и бизнес-правила:
1. Ограничения пользователей:
    * пользователь может иметь только одну учетную запись с уникальным email;
    * пользователь должен быть авторизован для прохождения теста;
    * пользователь не может проходить тесты, не предоставленные преподавателем;
2. Ограничения тестов:
    * тест должен содержать не менее 5 и не более 20 вопросов;
    * каждый вопрос должен содержать минимум 2 варианта ответа (для закрытых типов);
    * у каждого вопроса должен быть хотя бы один правильный ответ;
    * тест не может быть опубликован без вопросов;
    * после публикации теста изменение структуры теста (вопросов и ответов) запрещено;
3. Ограничения прохождения теста:
    * пользователь не может пройти тест более 1 раза;
    * время прохождения теста ограничено значением, заданным при создании (от 10 до 60 минут);
    * по истечении времени тест автоматически завершается;
    * пользователь не может изменить ответы после завершения теста;
    * ответы сохраняются автоматически в процессе прохождения;
4. Валидация данных:
    * поля регистрации (email, пароль) являются обязательными;
    * email должен соответствовать корректному формату;
    * пароль должен содержать не менее 8 символов;
    * при создании теста все обязательные поля должны быть заполнены;
    * запрещена отправка пустых ответов (если вопрос обязательный);
5. Системные ограничения:
    * система должна предотвращать множественную отправку формы;
    * при потере соединения данные должны быть сохранены;
    * доступ к результатам теста возможен только для пользователя и преподавателя;

## Нефункциональные требования:
1. Производительность и масштабируемость
    •    Время отклика: страница должна загружаться не более чем за 2-3 секунды при стандартном соединении.
    •    Поддержка до 100 одновременно активных пользователей.
    •    Масштабируемость: способность системы увеличивать производительность при росте данных или пользователей.
2. Безопасность
    •    Аутентификация и авторизация: правила доступа пользователей.
    •    Шифрование: использование HTTPS, защита передаваемых и хранимых данных.
    •    Защита от атак: Меры противодействия стандартным уязвимостям.
3. Надежность и доступность
    •    Доступность: 99 процентов времени работы системы без сбоев.
    •    Отказоустойчивость: способность восстанавливаться после сбоев.
4. Удобство использования (Usability) и доступность (Accessibility)
    •    UX/UI: соблюдение требований к интерфейсу, логике навигации.
    •    Интуитивность: соответствие интерфейса отраслевым стандартам и ожиданиям целевой аудитории.

## Архитектура системы и технический стек:
1.    Клиентская сторона (Frontend)  пользовательский интерфейс, работающий в браузере (HTML, CSS, JavaScript)
    Функции: отображение данных, взаимодействие с пользователем, отправка запросов к API. 
    Технологии: React.
2.    Серверная сторона (Backend)  логика приложения, работающая на сервере (Web Server).
    Функции: обработка запросов клиентов, выполнение бизнес-логики, взаимодействие с базой данных, аутентификация. 
    Технологии: Node.js.
3.    База данных (Database)  система хранения данных (БД).
    Функции: персистентное хранение информации, упорядочивание данных. 
    Используемые типы: Реляционные (СУБД MySQL)


Подход к тестированию (QA):
* Подготовка: разработка тест-кейсов, чек-листов, выбор инструментов, на основе документации проекта.
* Обеспечение качества: непрерывная верификация и валидация; качество закладывается на каждом этапе, а не проверяется в конце; мониторинг и оптимизация методов разработки для обеспечения соответствия стандартам.
* Функциональное тестирование: проверка работы всех функций веб-приложения, форм и ссылок.
* API-тестирование: проверка корректности работы серверных методов.
* Тестирование верстки и UI/UX: корректность отображения.

Этапы разработки веб-приложения:
Этап 0 — Планирование и анализ требований (1–2 дня).
Этап 1 — Проектирование базы данных (2–3 дня).
Этап 2 — Backend (база API) (3–5 дней). 
Этап 3 — Frontend (основа UI) (4–6 дней).
Этап 4 — Интеграция (2–3 дня).
Этап 5 — Тестирование (3–4 дня).
Этап 6 — Оформление проекта (1–2 дня).
